# Run / verify Geobiom mobile app on emulator

End-to-end loop to get `apps/mobile` running and visually verified on
the Android emulator. Every step here was a real failure mode that
cost hours; do them in order, do not skip the pre-flight.

## 0. Pre-flight (DO NOT SKIP)

```bash
# emulator RAM floor — the #1 silent killer
for d in ~/.android/avd/*.avd; do grep -E 'hw.ramSize|vm.heapSize' "$d/config.ini"; done
```
- If `hw.ramSize < 4096M` → STOP. A 1.5/2 GB AVD makes `pm install`
  hang for hours and insta-crashes the app before JS (low-mem kill).
  APK size / dex2oat / ABI are RED HERRINGS. Fix: edit the dead AVD's
  `config.ini` → `hw.ramSize = 4096M`, `vm.heapSize = 512M`, then cold
  boot. Full detail: `memory/feedback_mobile_emulator_ram_floor.md`.
- `adb devices` — note whether an emulator is already up. If it is and
  RAM is fine, skip the cold boot.

## 1. Cold-boot emulator (only if RAM was wrong / none running)

```bash
"$LOCALAPPDATA/Android/Sdk/emulator/emulator.exe" -avd geobiom-test \
  -memory 4096 -no-snapshot -gpu swiftshader_indirect -no-boot-anim &
# wait: adb wait-for-device; poll: getprop sys.boot_completed == 1
# sanity: adb shell cat /proc/meminfo | grep MemTotal  (~4016096 kB)
```

## 2. Build a SMALL APK (x86_64-only)

`apps/mobile/android/` is **gitignored** (regenerated by `expo
prebuild`). Edits there (e.g. `app/build.gradle ndk{abiFilters
'x86_64'}`, `gradle.properties`) are dev-only, never committed, never
affect the release arm64 APK. The default 4-ABI debug APK is ~213 MB;
x86_64-only is ~67 MB.

```bash
export PATH="/c/Program Files/nodejs:$PATH"
cd apps/mobile && npx tsc --noEmit            # gate before any Gradle
# first time or after asset/native changes:
npx expo prebuild --platform android --clean
# ensure apps/mobile/android/app/build.gradle defaultConfig has:
#   ndk { abiFilters 'x86_64' }
cd android && ./gradlew :app:assembleDebug --console=plain
```
Run long Gradle via `run-bg-pipeline` (bg + ASCII end-signal monitor +
ScheduleWakeup). Verify ABI: `unzip -l .../app-debug.apk | grep
'lib/.*\.so' | sed 's#.*lib/##;s#/.*##' | sort -u` → only `x86_64`.

## 3. Install

```bash
adb install -r apps/mobile/android/app/build/outputs/apk/debug/app-debug.apk
```
- With a 4 GB emulator this is ~1 s. If it still hangs, RAM is the
  problem — re-check step 0, do NOT chase APK size again.
- Signature clash with a stale build → `adb uninstall ru.geobiom.mobile`
  first.
- **MSYS trap:** any `adb shell` / `adb push` with a `/data`, `/sdcard`
  or absolute device path MUST be prefixed `MSYS_NO_PATHCONV=1`, else
  git-bash rewrites it to `C:/Program Files/Git/...` and it fails
  silently. `adb root` works on the `google_apis` (non-Play) image but
  does NOT cure a RAM-starved install.

## 4. Launch + connect Metro

```bash
cd apps/mobile && export PATH="/c/Program Files/nodejs:$PATH"
nohup npx expo start --port 8081 > /c/tmp/metro.log 2>&1 &
# wait for "Waiting on http://localhost:8081"
adb reverse tcp:8081 tcp:8081
adb shell am start -n ru.geobiom.mobile/.MainActivity
```
First JS bundle: ~30-60 s. A black screen right after launch is
usually the runtime permission dialog (`GrantPermissionsActivity`) on
top — grant + relaunch:
```bash
for p in ACCESS_FINE_LOCATION ACCESS_COARSE_LOCATION; do \
  adb shell pm grant ru.geobiom.mobile android.permission.$p; done
adb shell am force-stop ru.geobiom.mobile
adb shell am start -n ru.geobiom.mobile/.MainActivity
```

## 5. Verify visually (mandatory)

No RN unit-test runner exists in this repo. Verification = `tsc
--noEmit` + screenshot. NEVER claim "works" without eyes on a screen:

```bash
sleep ~20            # let it paint
adb exec-out screencap -p > /c/tmp/mob.png
# then Read /c/tmp/mob.png
adb logcat -d -t 200 | grep -iE "ReactNativeJS|FATAL|JSException"
```
Healthy = logcat shows `ReactNativeJS: Running "main"` + no FATAL, and
the screenshot renders real UI (not 21 KB all-black).

## 6. Commit/push around a dirty, diverged main

`apps/mobile` work often coincides with a worktree whose tree has
**foreign uncommitted WIP** (parallel sessions) and an `origin/main`
that diverged by many commits. Do NOT stash/rebase the foreign WIP.
Land your commit via an isolated worktree:

```bash
git add <only your apps/mobile paths>
git commit -m "..." -- apps/mobile        # pathspec-scoped
L=$(git rev-parse HEAD)
git fetch origin main
git worktree add --detach /c/tmp/gbpN origin/main
cd /c/tmp/gbpN && git cherry-pick "$L" && git push origin HEAD:main
cd - && git worktree remove /c/tmp/gbpN --force; git worktree prune
```
(`/c/tmp/gbpN` may stay file-locked "busy" on Windows — harmless,
prune drops the registration; it frees later.) Then `gh run list
--branch main` until CI green. Capture the change as a patch first
(`git diff -- <path> > /c/tmp/x.patch`; `git apply` it in the fresh
origin/main worktree) when the local working tree is too messy to
pathspec-commit cleanly.

## 7. Dev-build verify blockers (READ before promising ForestPopup/map verification)

Full detail + the sha256 root cause: memory
`feedback_mobile_dev_verify_blockers.md`. Hard truths:

- **Black screen + adb `offline` after launch = stale snapshot boot.**
  Kill qemu, cold-boot per §1 (`-no-snapshot …`). Not RAM (that's §0).
- **Debug RN on the Windows emulator dials Metro at `10.0.2.2:8081`**
  which the host firewall / QEMU-NAT blocks (logcat:
  `ReactNativeJNI … Failed to connect to /10.0.2.2:8081`). `adb
  reverse` alone is NOT enough (it only maps `localhost`). Fix: with
  the app stopped, write into the debuggable app's prefs via
  `run-as`, then relaunch:
  `MSYS_NO_PATHCONV=1 adb shell "run-as ru.geobiom.mobile sh -c 'echo <b64> | base64 -d > /data/data/ru.geobiom.mobile/shared_prefs/ru.geobiom.mobile_preferences.xml'"`
  with `<string name="debug_http_host">localhost:8081</string>`
  (preserve existing keys) + `adb reverse tcp:8081 tcp:8081`.
- **`nohup … &` (Metro, gradle) DIES across Bash-tool turns.** Use the
  harness `run_in_background:true` — survives, notifies on exit.
- **Emulator may have NO internet** (host AdGuard VPN breaks QEMU NAT,
  same as Tailscale-broken): `adb shell ping 8.8.8.8` →
  `Network is unreachable` even with `-dns-server`. Then: no region
  download, no online soil/water/terrain, AND dev-build bundled
  assets fail (next point). Only the user can fix (disable VPN).
- **`maplibre-react-native@10.0.0-alpha.30` blanks the WHOLE map when
  glyphs fail to load** (not just symbols). Symptom: empty paper +
  only `Mbgl [Style]: Failed to load glyph range … Noto Sans …`.
- **Dev (Metro) build fetches the bundled basemap pmtiles + 18 glyph
  PBFs over the network** (`Asset…downloadAsync()` ← Metro). No net →
  glyphs/basemap fail → (prev point) blank map. A RELEASE APK embeds
  them → renders offline. So forest-render / ForestPopup verification
  needs either a stable emulator network OR a release APK; it is NOT
  a feature-code defect.
- **Release APK in this monorepo is broken**: `:app:createBundleRelease
  JsAndAssets` → `Unable to resolve … expo-router/entry.js from
  <repo-root>/.` (`@expo/cli export:embed` uses repo root, not
  `apps/mobile`). `react{ root=file("../../") }` did NOT fix it.
  Separate build-infra task — do not grind it in a verify session.
- A **debug-signed release APK** (`GEOBIOM_KS_PATH=<…/app/debug.
  keystore> -PGEOBIOM_KS_PASSWORD=android -PGEOBIOM_KS_ALIAS=
  androiddebugkey`) keeps the installed app's signature, so
  `adb install -r` PRESERVES app data (downloaded regions) — no
  re-download / no net. (Useful once §7 monorepo bundle is fixed.)
- Screenshots are 1080x2400; downscale via PIL (~760px) before Read,
  or the multi-image API rejects them.
